How This Report Works

Each component is evaluated against seven criteria covering structure, naming, tokens, native mappability, interaction states, assets, and Code Connect readiness. The report is self-contained — all content lives in a single file, making it easy to share and version with the design system.

01 — Assess
Evaluate a component
Inspect the Figma component against 7 criteria: layer naming, variant properties, token coverage, native mappability, interaction states, asset quality, and Code Connect readiness.
02 — Document
Write the component file
Create or update a .html file in assessment-src/components/. Each file contains the nav item, summary card, summary row, and the full assessment section.
03 — Build
Run the build script
Run node assessment-src/build.js to assemble all component files into this page. The nav, summary, and all sections are injected automatically.
04 — Ship
Push to GitHub
Commit and push. The updated report is immediately live on GitHub Pages. No framework, no build pipeline — just a single index.html.
Assessment Criteria

Each component is evaluated against seven criteria. The overall status reflects the weakest criterion — a single unresolved structural issue can block Code Connect linkability even when everything else passes.

ID Criterion What We Check
C1 Layer Structure & Naming Are layers named semantically (e.g. leading-icon, content) rather than left as Figma defaults (Frame 42, Group 7)? Is the hierarchy logical and free of unnecessary nesting?
C2 Variant & Property Naming Do variants and component properties use clear, consistent conventions? Are boolean properties expressed as true/false (not yes/no)? Are enum values lowercase and hyphenated?
C3 Token Coverage Are all color, spacing, typography, and radius values bound to design tokens rather than hardcoded? Token coverage determines how easily a native engineer can map design decisions to a token system.
C4 Native Mappability Does the component map cleanly to a standard native primitive (e.g. DisclosureGroup, Button, List)? Are there web-only patterns with no native equivalent?
C5 Interaction State Coverage Are all expected interactive states defined as variants — default, pressed, focused, disabled, error? Missing states force engineers to invent visual behavior.
C6 Asset & Icon Quality Are icons defined as vector components (not raster/PNG embeds)? Are they colored using tokens so tinting works natively?
C7 Code Connect Linkability Is the component a proper Figma component set? Are property names clean enough to map 1:1 to native parameters? Are Code Connect mappings registered?
Status Legend
Status Meaning
Ready Clean structure, maps well to native, Code Connect linkable as-is.
Needs Refinement Minor naming, structural, or token issues to fix before linking.
Requires Rework Significant structural or design issues — needs redesign before native translation.
Not Applicable Web-only concept with no native equivalent (e.g. hover tooltips).
