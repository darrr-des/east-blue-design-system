Carousel Item - Center Consolidate Rework Component link

The "focused" tile for a peeking carousel — 312×160, 18px vertical padding, 8px corner radius, Proxima Soft heading + BarkAda description + optional "learn more" action. 10 variants across mode (Dark Text / Light Text) × type (Default / with Icon / Headline) × hasTextLink (yes / no / Default) × hasPreamble (yes / no). Its sibling Carousel Item - Side (18543:3099) uses the same schema, tokens, and layer anatomy — it is 14 px shorter (146 vs 160) and otherwise identical.

Consolidate — merge Center + Side into one Carousel Item; move focus treatment to the container
A name like "Center" encodes carousel layout position as a structural component variant. Position and the visual treatment that follows (scale, opacity) are runtime layout state owned by the carousel container, not DS components. Ship one EBCarouselItem with the anatomy shared by Center and Side; let the carousel apply scale/opacity via scroll progress on native.
In Context

Center tiles sit in the focused slot of a peeking carousel — full opacity, full scale — while Side tiles flank them at a smaller visual weight. On native, that focus treatment is driven by scroll progress, not by swapping component identities.

Open Issues
  • Position encoded as a component name. "Center" and its sibling "Side" describe where the tile renders inside a carousel, not what the tile is. The 14 px height delta (160 vs 146) is the only structural difference — every token, layer, and property mirrors across both. A position-specific component is a layout anti-pattern. C1 · Layer Structure & Naming
  • hasTextLink is a three-value enum masquerading as a boolean. Values are yes, no, and a literal Default (Light Text mode only). Should be either a boolean (showAction: Bool) or a slot (action?: Button). C2 · Variant & Property Naming
  • type compounds two unrelated axes. Default, with Icon, and Headline mix slot presence (icon or not) and content-weight (headline-only vs heading+description). These are orthogonal — should be split into a leadingIcon? slot and a variant: headline | standard property. C2 · Variant & Property Naming
  • Position is layout, not component identity. SwiftUI .scrollTransition and Compose graphicsLayer { pageOffset } express focus treatment as a runtime transform. Shipping a "Center" component blocks both platforms from their idiomatic path. C4 · Native Mappability
  • No pressed, focused, or disabled state. The tile is interactive (tappable + an embedded "learn more" button) but only the static rest state is modeled. C5 · Interaction State Coverage
  • Hero image is a baked raster. imgAssetDark / imgModeLightTextTypeDefaultHasTextLinkYesHasPreambleNo are placed as PNGs on the tile, not as an Image slot. Promo artwork is per-campaign — it must be a slot so consumers swap in their own asset without detaching. C6 · Asset & Icon Quality
  • Chevron is a raster PNG. imgShapeFull in the "learn more" action is a raster image, not a vector glyph — blurs at scale and blocks token-based tinting. C6 · Asset & Icon Quality

Design Recommendations
  • Merge "Center" + "Side" into one Carousel Item. Same width (312), same anatomy, same tokens. Promote the 160 px height as the tile's intrinsic height; retire the 146 px variant. Position-specific styling (scale, opacity) lives in the carousel container on native. Family
  • Move focus treatment to the carousel container. On native, scroll progress drives the transform: iOS ScrollView + .scrollTargetBehavior(.viewAligned) + .scrollTransition { c, p in c.scaleEffect(p.isIdentity ? 1 : 0.92).opacity(p.isIdentity ? 1 : 0.7) }; Compose HorizontalPager + graphicsLayer { val o = pageOffset.absoluteValue.coerceIn(0f, 1f); scaleX = lerp(0.92f, 1f, 1f - o); alpha = lerp(0.7f, 1f, 1f - o) }. No "Center"/"Side" component variants required. Composition
  • Rename the tile to remove the positional suffix. "Carousel Item - Center" → "Carousel Item". Names like "Center" / "Side" describe layout position — a smell that the abstraction is wrong. Rename
  • Collapse hasTextLink to a boolean. hasTextLink: yes | no | Default → showAction: Bool (or a nullable action slot). The literal Default value reads as a typo and only appears on one mode. Property
  • Split type into variant + leadingIcon?. Default | with Icon | Headline compounds unrelated axes. Extract an icon slot and keep a content-weight property: variant: standard | headline. Property
  • Add a hero image slot. The promo artwork varies per campaign — it must be an Image slot (instance-swappable), not a baked raster. Slot
  • Vectorize the chevron. Replace shape_full raster with a vector icon so color binds to text/color-text-primary / text/color-text-inverse and stays crisp. Asset
  • Add pressed + focused states. Tile is tappable with an embedded action — needs at least a pressed tint and a keyboard/D-pad focus ring. State
  • Document the carousel as a composition, not a roster of cards. The Carousel family today lists five separate components (Card, Discount Card, Item, Item - Center, Item - Side). Reframe as one tile composed by one container; document the per-tile variant matrix once. Docs
  • See siblings: Carousel Item - Side, Carousel - Item, Carousel Card, Carousel - Discount Card. The whole family is a single consolidation candidate — one tile + one container. Family

Usage — post-consolidation

The container owns focus treatment; the tile is identity-agnostic. No "center" or "side" appears anywhere in the API.

// Peeking carousel — container drives the focus transform
ScrollView(.horizontal, showsIndicators: false) {
    HStack(spacing: 12) {
        ForEach(promos) { promo in
            EBCarouselItem(
                mode: promo.darkText ? .dark : .light,
                image: Image(promo.asset),
                preamble: promo.preamble,
                heading: promo.heading,
                description: promo.body,
                action: .init("Learn more") { open(promo) }
            )
            .scrollTransition { content, phase in
                content
                    .scaleEffect(phase.isIdentity ? 1.0 : 0.92)
                    .opacity(phase.isIdentity ? 1.0 : 0.7)
            }
        }
    }
    .scrollTargetLayout()
}
.scrollTargetBehavior(.viewAligned)
// Peeking carousel — container drives the focus transform
HorizontalPager(
    state = pagerState,
    contentPadding = PaddingValues(horizontal = 40.dp),
    pageSpacing = 12.dp
) { page ->
    EBCarouselItem(
        mode = if (promos[page].darkText) EBCarouselItemMode.Dark else EBCarouselItemMode.Light,
        image = { Image(painter = painterResource(promos[page].asset), contentDescription = null) },
        preamble = promos[page].preamble,
        heading = promos[page].heading,
        description = promos[page].body,
        action = { TextButton(onClick = { open(promos[page]) }) { Text("Learn more") } },
        modifier = Modifier.graphicsLayer {
            val offset = ((pagerState.currentPage - page) + pagerState.currentPageOffsetFraction)
                .absoluteValue.coerceIn(0f, 1f)
            scaleX = lerp(0.92f, 1f, 1f - offset)
            scaleY = scaleX
            alpha  = lerp(0.7f, 1f, 1f - offset)
        }
    )
}

Usage Guidelines
Do
  • Ship one EBCarouselItem tile — let the carousel container drive focus treatment.
  • Use mode: light for dark hero images, mode: dark for light hero images.
  • Keep preamble short (one or two words) — it's a category tag, not a subtitle.
  • Always ship a destination — tiles are tappable, not informational-only.
Don't
  • Don't encode position ("Center", "Side") as a component name.
  • Don't bake the hero image — use an image slot so campaigns can swap assets.
  • Don't rely on the placeholder icon — replace with an instance-swappable Icon slot.
  • Don't pair Light Text mode with an image that lacks a dark scrim.
