Carousel Item - Side Remove N/A Component link

A 312×146 card intended as the "unfocused neighbor" rendition of Carousel Item - Center (312×160). 10 variants — 5 layouts (Default + TextLink, with Icon, Default + Preamble, Headline + Preamble, Default no link) × 2 color modes (Dark Text / Light Text). Schema, tokens, layer structure, and content are identical to Center; the only difference is a 14 px shorter frame. Position/focus behavior is a carousel-container concern, not a component concern — this component should not exist.

Remove — position is not a component axis
"Side" encodes where in the scroll the card is, not what the card is. Native carousel APIs already handle focus-aware scale and opacity at runtime: SwiftUI's .scrollTransition on a .scrollTargetBehavior(.viewAligned) ScrollView, and Compose's HorizontalPager + graphicsLayer with pageOffset. Fold Side + Center into one Carousel Item component and let the carousel container apply the step-down treatment.
In Context

Side is used in peek-style carousels where neighbor cards appear partially visible on the left and right of the focused card. The implicit contract: the focused card uses Carousel Item - Center (312×160), and the two flanking cards swap in Carousel Item - Side (312×146) to create a height/focus hierarchy. In a native carousel this same effect is produced at runtime by scroll position, not by swapping components.

Native Handling Planned API

No dedicated native component. The "Side" treatment is a runtime focus effect applied to a single EBCarouselItem inside a position-aware scroll container. Below is the canonical implementation.

// No EBCarouselItemSide. One component, runtime focus transform.
ScrollView(.horizontal) {
    LazyHStack(spacing: 12) {
        ForEach(items) { item in
            EBCarouselItem(
                mode: item.mode,
                layout: item.layout,
                heading: item.heading,
                description: item.description
            )
            .scrollTransition { content, phase in
                content
                    .opacity(phase.isIdentity ? 1 : 0.7)
                    .scaleEffect(phase.isIdentity ? 1 : 0.91)
            }
        }
    }
    .scrollTargetLayout()
}
.scrollTargetBehavior(.viewAligned)
// No EBCarouselItemSide. One component, runtime focus transform.
HorizontalPager(
    state = pagerState,
    contentPadding = PaddingValues(horizontal = 32.dp),
    pageSpacing = 12.dp
) { page ->
    EBCarouselItem(
        mode = items[page].mode,
        layout = items[page].layout,
        heading = items[page].heading,
        description = items[page].description,
        modifier = Modifier.graphicsLayer {
            val offset = (pagerState.currentPage - page +
                          pagerState.currentPageOffsetFraction).absoluteValue
            alpha  = lerp(0.7f, 1f, 1f - offset.coerceIn(0f, 1f))
            scaleY = lerp(0.91f, 1f, 1f - offset.coerceIn(0f, 1f))
            scaleX = scaleY
        }
    )
}

Usage Guidelines
Do
  • Use Carousel Item - Center (or the renamed unified Carousel Item) for every card.
  • Apply focus-aware scale + opacity at the container level.
  • Document the peek-carousel recipe in the Carousel component's guidelines.
Don't
  • Don't place Side instances in a new carousel — use Center only.
  • Don't map Side to a separate native component or Code Connect entry.
  • Don't encode scroll position as a component axis in any future component.
  • Don't add new variants here — work on Center instead.
