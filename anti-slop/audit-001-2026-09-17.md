# antislop audit 001 — 17 September 2026

Mode 2 (after the fact) on the assessment copy. Scope: every prose field of the
97 component files in `astro-site/src/content/components/`. Run with
`node astro-site/scripts/audit/antislop-copy-scan.mjs`.

**Not scanned, deliberately.** Spec rows, colour tables, variant rows, tokens,
code blocks and preview HTML are data, not copy. The em dash in a spec value is
the framework's "could not be read" marker (Rule Zero), and sweeping it would
destroy meaning. The review guides, `CLAUDE.md` and the `.astro` pages were also
left out of this pass.

## What came back clean

No buzzwords from R-16 or the empty-AI-vocabulary list. No negative parallelism,
no staccato drama, no aphorism formulas, no false ranges, no forced rule of
three. No signposting, no chatbot closers, no fake-candid openers, no weasel
attributions, no stacked hedging, no all-caps emphasis. Across 97 files, three
findings follow.

## Findings

### 1 — HIGH — R-02 — Em dash in prose, 3,433 occurrences in all 97 files

R-02 forbids the em dash in any text. Every component file uses it, most often
as a connector or an aside: "…boolean show/hide properties — no duplicate
variants needed", "…merged into Action Row — see that page for current DS
Health". Densest fields: changelog bodies (1,052), resolved issues (413), trait
notes (173), guideline don'ts (138).

Two things make this a decision rather than a defect. The copywriting skill
names em dashes as a false positive on their own and says not to rewrite a
deliberate style without saying so, and this is plainly deliberate: the same
voice runs through the guides and `CLAUDE.md`. The repo also forbids scripted
find-and-replace on string fields, so clearing this means a reviewed pass, not a
regex.

Options, smallest first: leave it and record the exception; convert only the
copy readers meet first (`meta.description`, `verdict.title`, `verdict.text`,
about 200 occurrences); or convert all prose fields file by file.

### 2 — HIGH — R-36 — Unevidenced superlative, 1 occurrence

`stepper-dash`, `scorecard[C6].notes`: "Best-in-class". A quality claim with no
measurement behind it. The rest of that note is specific, so the phrase can go
without a replacement.

### 3 — LOW — R-36 — Filler phrase, 1 occurrence

`upload-file`, `resolved[21].body`: "in order to", which is "to".

## Decision on finding 1 — R-02 waived for this repo

Recorded 17 September 2026. The em dash stays. It is the house voice, used the
same way in all 97 component files, the four review guides and `CLAUDE.md`, and
it carries meaning rather than decoration: "merged into Action Row — see that
page for current DS Health" is a pointer. The copywriting skill names an em dash
as a false positive on its own and says not to rewrite a deliberate style, and
this repo forbids scripted find-and-replace on string fields, so clearing 3,433
of them would be a hand pass over every component's prose for no reader benefit:
this is internal spec documentation, not marketing copy.

Half a migration was the option to avoid. Converting only the header fields
would leave a description with no dashes above a changelog full of them, which
reads worse than either end state.

If the em dash is ever dropped, the route is per component at its next Style,
Code or Changelog review, where someone is already reading and rewriting that
page's copy, rather than one sweep across the estate.

The scanner keeps counting them, so the waiver stays visible rather than
becoming a silent exception.
