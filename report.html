How This Report Works

Each component is evaluated against seven criteria covering structure, naming, tokens, native mappability, interaction states, assets, and Code Connect readiness. The report is self-contained — all content lives in a single file, making it easy to share and version with the design system.

01 — Assess
Evaluate a component
Inspect the Figma component against 7 criteria: layer naming, variant properties, token coverage, native mappability, interaction states, asset quality, and Code Connect readiness.
02 — Document
Write the component file
Create or update a .html file in assessment-src/components/. Each file contains the nav item, summary card, summary row, and the full assessment section.
03 — Build
Run the build script
Run node assessment-src/build.js to assemble all component files into this page. The nav, summary, and all sections are injected automatically.
04 — Ship
Push to GitHub
Commit and push. The updated report is immediately live on GitHub Pages. No framework, no build pipeline — just a single index.html.
Assessment Criteria

Each component is evaluated against seven criteria. The overall status reflects the weakest criterion — a single unresolved structural issue can block Code Connect linkability even when everything else passes.

IDCriterionWhat We Check
C1Layer Structure & NamingAre layers named semantically (e.g. leading-icon, content) rather than left as Figma defaults (Frame 42, Group 7)? Is the hierarchy logical and free of unnecessary nesting?
C2Variant & Property NamingDo variants and component properties use clear, consistent conventions? Are boolean properties expressed as true/false (not yes/no)? Are enum values lowercase and hyphenated?
C3Token CoverageAre all color, spacing, typography, and radius values bound to design tokens rather than hardcoded? Token coverage determines how easily a native engineer can map design decisions to a token system.
C4Native MappabilityDoes the component map cleanly to a standard native primitive (e.g. DisclosureGroup, Button, List)? Are there web-only patterns with no native equivalent?
C5Interaction State CoverageAre all expected interactive states defined as variants — default, pressed, focused, disabled, error? Missing states force engineers to invent visual behavior.
C6Asset & Icon QualityAre icons defined as vector components (not raster/PNG embeds)? Are they colored using tokens so tinting works natively?
C7Code Connect LinkabilityIs the component a proper Figma component set? Are property names clean enough to map 1:1 to native parameters? Are Code Connect mappings registered?

A. Native Mobile Translatability
A1 — What Works Well
  • Simple horizontal row layout maps directly to HStack/Row in both platforms with no web-specific layout assumptions.
  • Collapsed/expanded toggle maps cleanly to DisclosureGroup (SwiftUI) or AnimatedVisibility in a Column (Compose).
  • Chevron icons are confirmed Figma component instances (vector paths) — export cleanly as SVG/PDF for iOS or VectorDrawable for Android.
  • All spacing and padding values are tokenized (space/space-12, space/space-16).
  • Color tokens explicitly separate collapsed and expanded states, allowing direct 1:1 mapping to native color resources.
A2 — Issues & Recommendations
Missing Interaction States — Resolved in v3

Resolved: Pressed and disabled states added via Figma MCP. Engineers can reference state=pressed and state=disabled directly. Focused state (a11y focus ring) is still not defined but is lower priority for initial native handoff.

Expanded Content Panel — Resolved in v4

Resolved:content-body slot added to all 12 expanded variants. Background #F4F7FB, border #E5EBF4. Native engineers can now reference the defined content area in both DisclosureGroup (SwiftUI) and AnimatedVisibility (Compose) implementations.

Custom Fonts — Device Availability

Issue: Label uses "Proxima Soft" and description uses "BarkAda" — neither are system fonts on iOS or Android and must be bundled.

Recommendation: Confirm both fonts are bundled in native apps. Map tokens to UIFont(name:) / Font.custom() on iOS and fontFamily in the Compose theme on Android.
